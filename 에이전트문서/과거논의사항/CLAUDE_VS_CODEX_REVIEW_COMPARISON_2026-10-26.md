## 2. Codex 문서에서 좋은 부분 (Claude가 받아들일 것)

### 2-1. 로봇 미체결이라는 "이미 있는 리스크"를 정확히 짚었다 → Claude 분석 정정

- Claude는 "사람 공정은 정지형이라 불량이 안 생기고, 그래서 검사가 긴장 없는 연출이 된다"고 썼습니다.
- Codex는 **로봇 공정이 흐름형이라 팔이 차를 따라가지 못하면 미체결이 생긴다**는 점을 정확히 짚었습니다.
- 앞 공정을 자동화하면 사람이 만들던 정차가 사라져 **뒤 로봇의 작업 시간이 줄어든다**는 상호작용도 짚었습니다.
- 이것은 **새로 만들 필요 없이 이미 코드에 있는 딜레마**입니다. Claude가 제안한 "사람 공정에 택트 게이트 신설"보다 변경 범위가 작고, 기존 설계 의도(원안 §1)에도 더 충실합니다.
- Claude 문서에는 정정 주석을 달았습니다.

### 2-2. "원인을 보여주지 않으면 최적화가 아니라 억울함"

> "업그레이드했는데 왜 나빠졌지?"

- 이 지적이 이번 비교에서 가장 중요한 보완점입니다.
- 공장 게임의 재미는 병목을 **진단**하는 데서 나옵니다. 그런데 현재 프로젝트에는 원인을 표시하는 장치가 하나도 없습니다.
  - 공정별 대기 시간, 미체결 원인 공정, 처리량 그래프 모두 없음
  - `WorkerStatusUI`는 상태 아이콘만 보여줌
- 검사 실패에서 원인 공정으로 바로 이동하는 기능은 **우선순위 최상위**에 넣어야 합니다.

### 2-3. 그 밖에 받아들일 것

- **정상 차량의 검사 연출 템포**: 방수 크레인은 12단계 상태 머신입니다. 매번 풀 연출을 보여주면 처리량을 막고 지루해집니다. 첫 통과와 실패만 크게 보여주고, 정상 차량은 압축하자는 제안이 옳습니다.
- **경제 불균형**: 체결 보상은 불량이 나도 남습니다. 그래서 "불량을 내도 부품 보상은 받는" 구조가 될 수 있습니다. 장기 수익의 중심을 정상 납품과 주문 달성으로 옮겨야 합니다. Claude가 놓친 부분입니다.
- **고용(생산 능력)과 주문(생산 목표)의 분리**: 지금은 고용하면 계약 내용이 자동으로 바뀝니다. 둘을 떼어야 "어떤 주문을 받을지"가 선택이 됩니다. Claude의 "계약 캠페인"보다 플레이어 주도권이 큽니다.
- **주문 선택권**: Claude 안에서는 계약이 주어지기만 합니다. 플레이어가 주문을 **고르게** 하면 의미 있는 선택이 하나 공짜로 생깁니다.
- **고객 가정의 명시**: "편안하게 구경하는 고객"과 "능동적으로 최적화하는 고객" 중 누구를 우선할지 질문을 남겨 둔 점이 좋습니다(4장에서 답합니다).
- **시장 근거의 정직성**: 공식 페이지에서 직접 확인한 수치만 썼습니다. Little Big Workshop 평가는 Claude 쪽이 85%(3rd-party), Codex 쪽이 82%(공식 영어 리뷰)입니다. **공식 수치를 우선합니다.**

## 3. Codex 문서에 보완하거나 반박할 부분

### 3-1. 반박: "로봇에 아무 제약도 두지 말 것"은 Codex 자신의 실패 조건에 걸린다

- Codex는 "자동화의 보상을 지키기 위해 고장·정비·피로를 넣지 말라"고 했습니다.
- 같은 문서에 이런 판정 기준도 있습니다:
  > "항상 같은 투자만 정답이면 주문·비용·공정 차이가 부족하다."
- 로봇이 사람보다 **모든 면에서 낫다면**(빠르고, 관리가 없고, 미체결은 속도만 낮추면 해결), 어떤 주문이 와도 정답은 "돈이 되는 대로 로봇"입니다. 결국 현재 문제("로봇이 최종 해결책")가 주문 구조 아래에서 그대로 재현됩니다.
- **절충안**: Codex의 우려대로 **고장과 정비 같은 반복 관리 노동은 넣지 않습니다.** 대신 **능력 제약**을 둡니다. 플레이를 귀찮게 하는 대신 계획 단계에서만 작동하는 제약입니다.
  - 로봇은 지정된 작업만 합니다. 옵션 부품(예: 선루프)은 그 옵션용 로봇이나 사람이 있어야 합니다.
  - 주문이 바뀔 때 로봇 재설정에 비용이나 시간이 듭니다(차종 전환).
  - 효과: 옵션형 소량 주문에는 사람이 유리하고, 기본형 대량 주문에는 로봇이 유리해집니다. **Codex가 제안한 두 주문 유형이 실제로 다른 최적해를 갖게 됩니다.**

### 3-2. 보완: 주문 차이가 "수량과 작업량"만으로는 얕다

- Codex 스스로 "주문이 이름·수량·보상만 다른 반복 과제면 재미가 늘지 않는다"를 위험으로 꼽았습니다. 그런데 제시한 차이는 생산량과 공정별 작업량뿐입니다.
- 주문마다 **구조적으로 다른 병목**이 생기게 하려면 최소한 다음 중 하나가 필요합니다.
  - 옵션 부품이 **특정 공정**에 몰리는 구조. 병목 위치가 주문마다 바뀝니다.
  - 위 3-1의 로봇 능력 제약. 투자 우선순위가 바뀝니다.
  - 품질 기준 차이. 예를 들어 프리미엄 주문은 미체결 1건만 나와도 실패여서, 라인 속도를 공격적으로 올리기 어렵습니다.

### 3-3. 보완: 안돈과 자동 정지(Jidoka)는 "로봇 쪽"에 붙이면 Codex 원칙과 맞는다

- Claude는 사람 공정에 안돈을 제안했는데, 2-1에서 본 것처럼 사람 쪽을 바꾸는 것은 불필요했습니다.
- 대신 **로봇 미체결 리스크에 대한 선택지**로 안돈을 쓸 수 있습니다.
  - 설비 업그레이드로 "미체결 감지 시 라인 정지 센서"를 삽니다. 장점은 불량 0, 단점은 정지 시간 손실입니다.
  - 센서가 없으면 미체결 차가 검사까지 흘러가 연출과 함께 폐기됩니다.
- 이렇게 하면 **새 반복 조작 없이** "속도 대 품질" 판단이 생깁니다. TPS 용어(Jidoka)는 디지털트윈 포트폴리오 이야기와도 연결됩니다.

### 3-4. 보완: "사람 관리"라는 정체성 문제를 피했다

- `AGENTS.md`의 한 줄 정의는 "실제로는 사람 관리 게임"입니다. 두 추천안 모두 사실상 **공장장(생산 운영) 게임**입니다.
- Codex 안에서는 사람이 "느리지만 확실한 초기 수단"에 머뭅니다. 관리 대상이라기보다 로봇의 전 단계입니다.
- 판단: 정체성을 **"생산 운영 게임"으로 공식 변경**하는 편이 정직합니다. 다만 사람의 역할을 남기려면 3-1의 능력 제약이 필요합니다(옵션과 예외 작업은 사람 몫). 작업자 개별 특성(Claude 안)은 **검증판 이후로 보류**합니다. Codex가 우선순위를 더 정확하게 봤습니다.

### 3-5. 보완: 기술 선행 과제가 빠져 있다

어떤 방향을 고르든 검증판 전에 필요한 것들입니다(Claude 분석 기준).

- 빌드 설정에 `SampleScene` 하나만 있음 → 외부 플레이테스트 자체가 불가능합니다.
- 라인 속도를 조절하는 `UpgradeLineSpeed`를 호출하는 곳이 없음 → Codex 검증판의 "조절 가능한 가동 속도"는 **이 부분을 먼저 연결해야** 가능합니다.
- 가격식과 수치가 코드에 하드코딩 → 주문 2~3종을 반복해서 밸런싱하려면 SO나 테이블 분리가 먼저입니다.
- 미커밋 대규모 씬 변경(+14,988/−12,809줄) → 실험 브랜치를 따기 전에 정리해야 합니다.

### 3-6. 시장 판단 보완

- Codex는 "판매량을 예측할 수 없다"에서 멈췄습니다. 신중한 태도지만, **기대치를 정하는 데**는 기준선이 필요합니다.
- Claude 조사의 기준선 (3rd-party 추정):
  - 직접 경쟁작 Production Line: 약 7만 장, 약 $1.1M
  - 1인 개발 성공 벤치마크 Opus Magnum: 약 11만 장
- 의미: 이 틈새는 "대박"이 아니라 **"잘하면 1인 개발이 지속 가능한" 규모**입니다. 그래서 범위 통제(자유 배치 배제)가 더 중요하다는 두 문서의 공통 결론을 뒷받침합니다.

## 4. 쟁점별 최종 판단

| 쟁점 | 결정 | 근거 |
|---|---|---|
| ① 로봇 제약 | **고장·정비는 넣지 않고, 능력 제약(지정 작업, 차종 전환 비용)은 넣는다** | 반복 노동 없이 "항상 로봇이 정답"을 막는 최소 장치 |
| ② 품질 리스크 원천 | **기존 로봇 미체결 + 라인 속도 조절** (Codex 안). 사람은 확실한 완성을 유지 | 이미 구현돼 있고, 변경 범위가 최소 |
| ③ 혼합 생산 | **주문 배치 단위**로 시작(Codex 안). 혼류는 확장 콘텐츠로 | 검증판 범위 축소. 주문 사이의 전환 자체가 결정 |
| ④ 사람 특성과 배치 | **보류.** 검증 통과 뒤 "옵션 작업 전담" 같은 역할로 재검토 | 핵심 재미 검증에 불필요 |
| 고객 우선순위 | **"가볍게 최적화하는 고객"** (Mini Motorways / Opus Magnum 라이트층). 감상의 즐거움은 연출로 유지 | 감상만으로는 장기 판매 근거가 약함. 깊은 최적화층은 Factorio가 독점 |
| 진단 UI | **검증판 필수 요소로 격상** | 원인을 모르면 선택이 아니라 추측 |
| 엔딩 | "전 라인 로봇화"는 **이정표**로 두고, 최종 목표는 주문 캠페인 완결 | 두 문서 합의 |
| 급여, 파업, 연구 트리, 지게차, 달력 | **보류** | 두 문서 합의 |

## 5. 통합 검증판 사양 (두 문서의 합본)

**구성** (기존 `Car_Factory 3`의 첫 줄을 활용)

- 조립 4공정. 사람과 로봇을 섞을 수 있게 합니다. 검사는 기존 흔들기 하나만 둡니다.
- **라인 속도 슬라이더.** `UpgradeLineSpeed`를 연결합니다.
- 주문 2종 중 플레이어가 선택합니다.
  - **기본형 대량**: 20대, 대당 보상 낮음
  - **옵션형 소량**: 8대, 특정 공정에 옵션 부품 +1, 대당 보상 높음, 품질 기준 엄격
- 제한된 자금과 투자 선택 4가지: 로봇 도입, 로봇 강화, 보급 강화, 미체결 정지 센서
- 로봇 능력 제약 하나: 옵션 부품은 사람이나 옵션 로봇만 체결할 수 있습니다.
