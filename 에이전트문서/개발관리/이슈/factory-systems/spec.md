# 2차 프로토타입 공장 시스템 통합 순서

11월 13일 작업 우선순위. 제품 규칙은 [현행 게임 설계](../../../GAME_DESIGN.md) 첫 절을 따른다. 아래 순서는 개발 계획이며 벽 모양, 가격, 창고 재고 경제를 확정하지 않는다.

| 순서 | 기존 동작과 연결할 지점 | 플레이에서 확인할 결과 |
| --- | --- | --- |
| 1. 공장 구역 개방 | FirstProductionLoop가 열린 공정 수로 설비·재고·벨트를 조절한다. FactoryExpansion은 prototypeMode에서 전체 구역을 강제로 열고 행 단위로 바닥을 계산한다. 둘이 같은 해금 상태를 읽게 한다. | 시작 시 세척·대시보드·납품과 창고 접근로를 확보한다. 후속 설비와 조작 표지는 감춘다. 미개방 작업 구역 진입을 막아야 하는 위치에는 가시적인 안전 펜스를 사용한다. 같은 행의 다음 공정과 다음 행 개방을 각각 표본 검사한다. 기존 계약 차량과 납품 대차의 이동을 방해하지 않는다. |
| 2. 창고 보급 | SupplyManager의 부족 재고 선택·예약과 SupplyWorker의 창고 적재·운반·하역을 재사용한다. 새 루프에서 꺼진 PrototypeServicesInteraction의 창고 접점을 복구하고 초기 재고를 다 쓴 경우의 회복 경로를 점검한다. | 열린 공정의 재고 소진 → 창고 보급 → 슬롯 복구 → 다음 차량 작업 재개. 잠긴 공정에 배달하지 않고, 새로 열린 공정은 보급 대상에 편입된다. 잔액 부족과 품절이 겹쳐 진행이 영구 중단되는지 확인한다. |
| 3. 투자와 생산 운영 | 첫 고용 전용 구매를 열린 공정별 고용·로봇화로 연결한다. 수동 투입에서 구매형 자동 투입으로 전환하고 대기열·정체·일과 정산을 새 납품 경제와 연결한다. | 플레이어가 한 공정을 맡기고 다른 업무를 동시에 할 수 있다. 여러 대를 넣어도 작업·재고·대금이 차량별로 유지되고 일과 정산에서 수입이 중복되지 않는다. |
| 4. 완성차 검사·출고 | 중간 납품과 최종 검사 진입을 구분하고 기존 검사·출고 자산을 재사용한다. 수밀 입구 체결 마감 → 수밀 → 주행 → 체결 확인 순서를 따른다. | 서로 다른 조립 상태의 차량에서 정상 출고와 불량의 원인·결과가 보인다. 최종 스캔·폐기 연출의 디테일 및 검사 해금 시점은 현행 설계의 후순위·미결 사항을 유지한다. |
| 5. 관리·진행 유지 | 현장 생산 상태를 태블릿으로 조회하고 공장 성장 상태의 저장·복귀를 연결한다. | 해금·고용·자동화·자금이 재실행 뒤 일치하며 태블릿을 닫으면 기존 시점으로 돌아온다. 원격 구매 범위와 운행 중 차량 저장 정책은 별도 결정이다. |

1·2번의 구현과 메인 씬 검증은 [구역 경계와 창고 접근·보급](issues/01-area-and-warehouse.md)에 기록했다. 3번 중 [공정별 고용과 로봇 전환](issues/02-process-staffing.md)을 완료했다. [자동 투입·대기열·정체](issues/03-automatic-input.md) 확인 후 [하루 운영·정산](issues/04-day-settlement.md)까지 연결했다. 4번 [완성차 검사·출고](issues/06-final-inspection.md) 프로토타입을 연결했다. 5번 [현장 태블릿과 공장 성장 저장](issues/07-tablet-and-save.md)도 메인 씬에서 확인했다. 이 다섯 영역은 대표 흐름으로 검증했다. [최종 주유](issues/08-final-fueling.md)도 메인 씬에서 직접·고용·자동 각 한 대와 불량 차량 통과를 확인했다. 완성차 두 대 통합 검사에서도 6.3m 대기 간격, 투입 순서대로 주유·출고, 계약마다 1회 지급을 확인했다. 핵심 공장 흐름의 대표 통합 검사를 완료했다. 아래 리뷰에 진행 차단 수정과 검증 범위를 기록했다. 고용과 해금의 비용·보상 비교는 후속 레벨 디자인에서 다룬다.

## 검사·출고 구현 전 대조 기록

메인 루프는 모든 차량에 중간 납품 계약을 배정한다. 완성차 검사를 연결할 때는 투입 시점에 인수 경로를 선택하고, 이미 들어온 중간 납품 차량의 대차와 단가는 유지한다. 기존 WaterTestStation은 크레인 침수 방식이고 InspectionLineSetup은 흔들기 다음 수조 배치를 저장하므로 현행 순서에 그대로 적용할 수 없다. 부품별 검사 판정과 DepartureStation의 출고 주행은 재사용 후보이며, 마지막 대금은 중간 인수와 완성차 출고 중 한 경로에서만 지급해야 한다. 검사 해금 단계는 아직 미정이다.

## 검증 범위

기존 실플레이로 첫 납품·다음 투입·고용·세 공정까지의 해금과 계약 금액 변화가 확인됐다. 같은 종류의 일반 체결 부품은 공정표로 처리하고 참조·순서 등 공통 규칙을 일괄 점검한다. 실제 플레이는 구역 경계, 품절·보급, 사람→로봇 전환, 바퀴·주유처럼 규칙이 다른 공정, 정상·불량 출고에 집중한다. 개별 위치와 손 그립은 제작자가 조정한 값을 보존하고 진행을 막는 경우에만 해당 지점을 조사한다.

통합 플레이 뒤 GAME_DESIGN 8장의 플레이 후 논의로 임시 비용·간격·난도를 조정한다. 블렌더 공장·차량 제작은 별도 작업이다.

이번 리뷰에서 재고 0개, 보급자 0명, 잔액 -1원, 고용비 0원의 조합이 창고 고용을 막는 것을 재현했다. 무료 보급자 고용의 UI·결제 조건을 일치시킨 뒤 같은 메인 씬에서 보급자 1명, 잔액 -1원 유지, 재고 12개와 집기 슬롯 활성, 1원 유료 지출 거절을 확인했다. 첫 차 세척 표면은 5,444점이었다. 세척 셰이더를 플레이어 빌드 포함 목록에 등록하고 Unity 직렬화 참조를 확인했다.

초반은 실제 입력 기록을 사용했고 후반 사례는 세척·조립 상태, 차량 위치 또는 시간을 준비했다. 26개 공정을 처음부터 연속 수동 완주한 결과는 아니다. Windows 64비트 플레이어 스크립트 컴파일로 Assembly-CSharp.dll 생성을 확인했다. 독립 실행 파일 플레이는 이번 검증 범위 밖이다. 메인·공정편집 씬이 참조하는 프로젝트 에셋 251개의 파일과 .meta가 공유할 Git 인덱스에 함께 있는지 대조했다. 사용자 저장을 보존하고 메인 씬 Edit 모드로 복귀했다.
