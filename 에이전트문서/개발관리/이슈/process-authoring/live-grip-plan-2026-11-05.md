# 실행 중 편집·잡기 위치 구현 계획
사용자가 2026-11-05 작업 진행을 지시하여 /01·/02 착수 보류를 해제했다. 기존 Unity/C#/손 IK와 공유 프로필을 확장한다. 신규 솔버·자동 보급 레일은 범위 밖이다.

## 설계 판단
- 실행 중 자동 이동하는 주체에는 저작 기준점을 사용한다. 정적 재고는 실제 Transform을 편집한다. 기준점/수치 변경만 초안에 캡처하고 자동 모션은 제외한다.
- 기존 양손 IK를 재사용한다. 공정의 슬롯 부품에 명시적 왼손/오른손 및 단일 로봇 접촉점을 부품 로컬 좌표로 저장한다. 기존 자동 그립은 미설정 시 유지한다.
- 로봇 운반은 부품 루트가 아니라 지정 접촉점이 팔끝을 따라가도록 역변환한다. 부품 회전 시에도 접촉점 오프셋을 다시 계산한다.
- 저장은 현재 초안을 공유 프로필에 기록하고 실행에 적용한다. 움직이는 주체의 저작값은 런타임 pose와 구분한다.

- [x] 실제 Play 대표 공정 작업자/로봇, 슬롯 재충전·재고·기존 프리뷰 회귀 검증.

## 구현 판단·발견
- Ruling: 새 전신 IK 없이 기존 WorkerHandIK를 기본으로 유지 — 문 대기 자세의 손 오차 원인은 깊이방향 두 지점/운반 회전과 도달 범위였다. package rig 시험만으로 해결되지 않았고 전면 교체 근거가 없다.
- 실행 중 Actor 바인딩은 저작 기준점, 정적 재고는 실제 Transform이다. 실제 작업자를 클릭하면 저작 기준점으로 선택을 연결한다. 수치/Scene/Undo/저장 중 자동 이동 pose를 캡처하지 않는다.
- 잡기 설정은 공정 부품 공통값이며 차종 그립보다 우선. 미설정/해제 시 원본·차종 그립을 복원한다. 명시적 왼손/오른손을 운반 도중 임의 교환하지 않는다.
- 슬롯 메시와 차량 부품에 음수 미러 스케일 차이가 있어 sourceScale/partScale 비율로 로컬 접촉점을 변환한다. 기즈모는 보이는 슬롯 모델 기준, 실제 손/로봇 목표는 변환된 부품 로컬 기준이다.
- 작업자 집기: 슬롯 중심 앞에 접근, 양손 ready IK, 최소 .3초 후 양손 손목-목표 각각 .12m 이내에 집기. 2초 동안 도달 못하면 재고 소모 없이 취소/사유 표시. 새 접촉 설정의 접근 도착 반경 .05m. 운반 전환 .35초.
- 로봇 집기: 명시적 접촉점에 팔끝 .04m 이내 접근 후 집기, 같은 프레임부터 역변환으로 접촉점 추종. 부품 회전과 차량 부착 회전 변화 반영.
- 독립 코드 검토 Important2건: Scene marker Capture가 DataChanged를 지우던 문제, 해제 시 기존 차종 그립을 잃던 문제. 둘 다 RED 재현 후 GREEN. 후속 검토 새 Important/Critical 없음(뒤에 추가한 미러 스케일 수정은 실제 실행 검사로 검증).
- 진단 중 RED: 기존 runtime 수치 반영0m, 로봇 첫 집기 접촉오차 .271m, pickup 기존 도착 반경/미러 스케일로 팔이 닿지 않음. 검사 자체의 빈 슬롯 ReadyDisplay null도 캐시된 sourceScale로 보완했다.
- 실행 중 저장 동기 검사: Paused=false/Running=true 상태에서 sentinel987.125를 공유 SO·디스크에서 확인하고 즉시 원본 복원. 자동 주체 Transform 변화를 설정에 캡처하지 않는 것도 확인. 테스트 값은 보존하지 않았다.
