## Problem Statement

개발자가 메인 공정의 작업자·로봇·부품 더미·단일 집기 슬롯·정차 위치를 한 곳에서 편집하고 실제 체결 모습을 확인할 수 없다. 기존 부품 테스트는 로봇팔 한 대 중심이며 메인과 차량 이동 경로가 달라 결과를 그대로 신뢰하기 어렵다. 고용 작업자의 외형 확인과 카메라 이동 규칙도 최신 요청에 맞춰 고쳐야 한다.

## Solution

메인과 같은 폭의 짧은 직선 레일을 갖는 새 공정 편집 씬과 전용 에디터 창을 만든다. 기존 TestPartsScene과 IK 비교 실험 씬은 보존한다. 편집 씬에서 공정·차종·작업 주체를 선택하고 Scene 뷰에서 배치를 수정해 저장한다. 메인과 편집 씬은 같은 설정 해석기와 공정 실행기를 사용한다.

배치 편집은 편집 모드에서 가능하고, 동작 확인은 Play에서 실행한다. 정지·재시도·배속 제어는 전용 창에서 제공한다. Play 중 조정한 저작 값도 명시적으로 저장할 수 있지만, 움직이는 차량/손의 순간 pose나 재고·진행 상태는 설정으로 저장하지 않는다.

### 확정 결정과 제안의 구분

사용자 확정: 고용 주유원도 공정 작업자와 같은 RobotKyle로 변경(2026-11-04 추가 승인). 원본 FBX 보존·기능 참조 재연결. 카메라 기준 이동으로 변경, 공정 작업자의 로봇 외형, 편집 도구 요구사항, **메인 작업자 공정도 정차 체결**, **작업 가능한 경우에만 정지/취소 시 정지 해제**, **기존 Animation Rigging으로 도구·대표 공정 먼저 검증**.

설계 제안: 아래 데이터 우선순위, 편집/Play 저장 UX, 재시도 초기화 정책, 무효 경로 처리, 카메라의 구체적인 빠른 회전 규칙. 승인 시 이 제안도 구현 기준이 된다. 수치와 내부 클래스 구성은 구현자가 정하고 검증 기록에 남긴다.

## Approaches

1. 기존 TestPartsScene 확장: 기존 로봇 테스트 UI는 재사용하기 쉽지만 단일 부품·별도 이동기를 기반으로 해 작업자·주유·메인 일치까지 바꾸면 기존 테스트 의미가 크게 달라진다.
2. **새 공정 편집 씬 + 메인과 공유하는 설정/실행기(권장)**: 초기 연결 작업이 필요하지만 저장 결과와 테스트 동작이 실제 게임으로 이어지고 기존 비교 씬을 보존한다. 새 씬 선택은 사용자가 에이전트에 위임한 판단이다.
3. 메인 전체를 편집/테스트 환경으로 사용: 실제 배치는 보이지만 경제·교통·고용·하루 진행과 섞여 공정 하나를 반복 튜닝하기 어렵다. 이번 목적에는 사용하지 않는다.

## User Stories

1. 개발자로서 카메라를 돌리며 W를 누르면 새 카메라 방향으로 이동하고 싶다. 이동 시작 때의 방향에 갇히지 않기 위해서다.
2. 개발자로서 우클릭 회전 중 캐릭터가 빠르게 방향을 맞추고 싶다. 시선과 조작 반응을 맞추기 위해서다.
3. 개발자로서 공정 작업자를 고용하면 기존 로봇 캐릭터가 보이고 집기·체결·귀환하기를 원한다. 외형 문제와 동작을 구분해 확인하기 위해서다.
4. 개발자로서 처음 도구를 열면 첫 공정과 차량이 준비되기를 원한다. 수동 조립 없이 바로 테스트하기 위해서다.
5. 개발자로서 실제 메인 공정 목록에서 선택하고 싶다. 목록을 두 번 관리하지 않기 위해서다.
6. 개발자로서 작업자/로봇 버튼으로 같은 공정의 주체를 바꾸고 싶다. 동일 조건의 동작을 비교하기 위해서다.
7. 개발자로서 공정의 모든 부품·좌우 주체·바퀴 조를 보고 개별 선택하고 싶다. 복합 공정을 누락하지 않기 위해서다.
8. 개발자로서 실제 레일 폭과 진행 방향 기준 좌우를 재현하고 싶다. 메인과 같은 도달거리 조건에서 튜닝하기 위해서다.
9. 개발자로서 공통 횡거리로 모든 공정의 주체를 가깝게/멀게 조절하고 싶다. 반복 편집을 줄이기 위해서다.
10. 개발자로서 개별 주체의 보정도 저장하고 싶다. 공정별 예외를 표현하기 위해서다.
11. 개발자로서 재고 더미와 집기 슬롯의 위치·회전을 마우스로 편집하고 싶다. 집기 출발점과 겹침을 직접 확인하기 위해서다.
12. 개발자로서 로봇 대기점과 감지 BoxCollider를 편집하고 싶다. 도달/감지/추적 종료 범위를 맞추기 위해서다.
13. 개발자로서 작업자의 일반 대기·체결 대기·차량 정차점을 서로 다른 표식으로 편집하고 싶다. 복귀와 작업 준비를 혼동하지 않기 위해서다.
14. 개발자로서 작업자 이동 곡선과 부품 이동 곡선을 따로 편집하고 싶다. 엔진 등에 접근할 때 몸이나 부품이 차량을 관통하지 않게 하기 위해서다.
15. 개발자로서 작업자와 로봇의 경로를 별개로 저장하고 싶다. 한 주체를 튜닝해 다른 주체의 동작을 망치지 않기 위해서다.
16. 개발자로서 1회 실행/자동 반복/일시정지와 0.1~20배속을 쓰고 싶다. 전체 흐름과 집기 순간을 모두 관찰하기 위해서다.
17. 개발자로서 체결 중에도 재시도하고 싶다. 주체가 대기로 복귀한 뒤 다시 집는 모습을 빠르게 확인하기 위해서다.
18. 개발자로서 고용 표지의 횡방향 공통 거리를 조절하고 진행방향 위치는 직접 고치고 싶다. 메인 표지 배치를 함께 정리하기 위해서다.
19. 개발자로서 저장 후 씬을 다시 열거나 메인을 실행해 같은 결과를 보고 싶다. 테스트 배치를 다시 손으로 옮기지 않기 위해서다.
20. 개발자로서 차종을 바꿔 부착점·그립·접근 경로를 보정하고 싶다. 다양한 차량 에셋을 지원하기 위해서다.
21. 개발자로서 주유의 작업자 대기·노즐 집기·차량 접근·주유구 연결·반납을 테스트하고 싶다. 체결 이외의 상호작용도 같은 환경에서 다루기 위해서다.
22. 개발자로서 도달 불가·차체 관통·미저장 변경을 명확히 보고 싶다. 잘못된 설정을 정상 완료로 착각하지 않기 위해서다.

## Implementation Decisions

### 하나의 설정 경계와 하나의 실행 경로

공정 카탈로그는 기존 생산 진행의 공정 목록을 읽는다. 편집기만의 수동 목록을 만들지 않는다. 공정은 안정적인 ID, 하위 작업은 주체/부품/슬롯 ID로 찾는다. 같은 PartType을 여러 주체가 쓰는 경우를 구분한다. 배열 순서나 표시 이름으로 저장 대상을 결정하지 않는다. 주유는 서비스 공정 어댑터로 같은 카탈로그에 포함한다.

설정 해석기는 공정 ID·차종 ID를 받아 유효한 최종 설정과 출처/검증 결과를 반환한다. 메인과 도구는 그 결과를 같은 공정 실행기에 전달한다. 시각적 프리뷰 때문에 체결/재고/차량 이동 로직을 복제하지 않는다. 기존 작업자·로봇·주유 코드는 필요한 어댑터를 통해 재사용한다.

### 저장 데이터 구분

| 범위 | 저장 항목 | 적용 기준 |
| --- | --- | --- |
| 공통 | 레일 참조/폭, 주체 횡거리, 고용 표지 횡거리, 프리뷰 기본 속도 | 모든 공정의 기준값 |
| 공정/주체 | 진행방향 위치, 좌우, 개별 횡거리 보정, 일반 대기, 체결 대기, 감지 영역, 정차점, 재고/슬롯 pose | 공통 기준에 명시적 보정 |
| 차종/작업 | 차량 프리팹·부품 매핑, 차량 로컬 부착 pose/그립, 주체별 접근·운반 곡선, 필요 시 대기/정차 보정 | 선택한 차종의 작업에만 적용 |
| 프리뷰 세션 | 선택 공정·차종·주체, 배속, 일시정지, 반복 여부 | 편의 상태이며 메인 진행 데이터와 분리 |

보정은 값 0과 ‘미설정’을 구별한다. 공통값 변경이 개별 보정에 합성되고 진행방향 수동값은 보존된다. 주체 전환은 다른 주체의 설정을 덮어쓰지 않는다. 기존 로봇 SO와 차량 조립 데이터는 유지/이관 어댑터로 읽으며, 이관 전후 같은 pose를 검증한다.

기존 Origin 차량에 신규 저작 설정이 없으면 기존 설정을 사용한다. 다른 차종에 부품 매핑/필수 pose가 없으면 미지원 항목을 표시하고 해당 테스트를 막는다. 다른 차량의 부착점을 조용히 대입하지 않는다. 새 차량 에셋 제작·임포트·기존 세단 아트 완성은 별도 트랙이다.

재고 자동 배치는 저작 데이터가 없는 경우에만 fallback으로 쓴다. 저장된 슬롯을 시작 시 다시 자동 이동하지 않는다. Count/TryConsume/TryTakePortable/Add와 준비된 인스턴스 토글·슬롯 예약·손 0.5m 이탈/최대1초 재충전 규칙을 유지한다.

### 좌표·레일·표식

위치는 라인 로컬 진행/횡방향/높이로 저장한다. 테스트 직선은 X 진행, Z 횡방향이지만 월드 X/Z를 모든 라인에 강제하지 않는다. 실제 진행방향에서 좌우를 정의하고 ±X 라인에 변환한다. 차종의 부착/그립 pose는 차량 로컬이다.

레일 폭은 실제 컨베이어 형상을 기준으로 가져온다. 기존 laneWidth 필드는 감지 영역 중심 계산값이므로 레일 폭으로 사용하지 않는다. 앞뒤 길이는 도달/감지 영역과 선택 차량 길이 바깥에 진입·진출 여유를 둔다. 카메라와 조명을 포함하고 모든 편집 요소는 의미별 하이어라키로 그룹화한다.

주체의 기본 진행좌표는 작업 중심에 두고 공통 횡거리·좌우를 적용한다. 개별 조절을 켜면 해당 주체의 보정만 저장한다. 고용 표지 역시 횡거리 공통+개별 보정과 진행방향 수동값을 분리한다. 원본 Post_00의 수동 진행위치는 유지한다.

### 편집·저장 UX

상단: 공정/차종/주체 선택, 저장/다시 불러오기, 메인 적용 확인. 실행 제어: 1회 실행, 자동 실행 토글, 일시정지/재개, 체결 재시도, 배속 감소/증가·현재값. Scene 뷰와 Inspector에서 같은 저작 항목을 편집한다.

재고·슬롯 pose, 대기점, 정차점, BoxCollider, 작업자 경로/부품 경로/팔 목표를 핸들로 표시한다. 주체를 감추어도 설정은 유지한다. 마우스 핸들은 Undo/Redo를 지원한다. 로봇 도달 반경, 작업자 접근/손 도달범위, 차량 외피와 교차 지점을 시각화한다.

저장은 선택 공정/차종의 명시적 저작 값과 변경한 공통값만 SO에 기록한다. 범위와 변경 항목을 표시한다. 메인은 같은 데이터를 다음 로드/Play 때 읽으며 기존 메인 씬 배치를 일괄 파괴/재생성하지 않는다. 편집 모드의 ‘메인 적용 확인’은 저장된 결과를 확인하는 명시적 동작이다. 저장 전 공정/차종 변경이나 씬 종료 시 저장/버리기/취소를 제공한다.

Play 중 저작 대상과 실행 pose를 분리한다. 저작 핸들 수정은 프리뷰 일시정지 상태에서 수행하고, 저장 후 재시도하면 반영한다. 움직이는 뼈/차량을 드래그한 결과를 설정으로 오인해 저장하지 않는다. .cs는 Play 중 생성/수정하지 않는다.

### 실행·배속·재시도

1회 실행: 시작점 차량을 진입시켜 선택 공정 작업 후 도달범위 밖으로 진출시키고 종료한다. 자동 실행: 같은 흐름을 반복한다. 일반 반복은 실제 테스트 재고 소모와 재고0 흐름을 관찰할 수 있게 유지한다. ‘초기 상태 복원’은 별도 동작이다.

체결 재시도: 진행 중 작업/예약/IK 목표/게이트를 취소하고 테스트 차량·재고를 해당 실행의 시작 스냅샷으로 복원한다. 주체를 일반 대기로 되돌린 뒤 동일 진입·집기 사이클을 재실행한다. 로봇은 대기 목표로, 작업자는 일반 대기 위치로 복귀한다. 복귀가 끝나기 전 재입력은 마지막 재시도 요청 하나로 합쳐 중첩 코루틴/소모를 막는다. 테스트 상태만 복원하며 메인 재고·경제·PlayerPrefs는 건드리지 않는다.

배속 목록은 0.1,0.2,…,0.9,1,2,…,20이다. 1의 감소는0.9, 0.9의 증가는1, 1의 증가는2다. UI/에디터 제어는 실제 시간으로 동작한다. 프리뷰만 실행되는 씬에서 시뮬레이션 전체가 같은 배율을 사용한다. 정지/씬 전환/예외/도구 종료 시 전역 시간 설정을 복구한다. 20배에서 놓치는 단계가 있으면 고정 스텝/서브스텝을 조정하고 비용을 검증한다.

### 작업자 정차와 중단

작업자 사이클: 일반 대기 → 유효 차량 감지 → 재고 예약·집기 → 체결 대기 이동 → 지정 정차점에서 차량 정지 확인 → 접근/운반 → 부착/망치 체결 → 정지 해제 → 일반 대기 복귀.

정지는 작업자 근무/컨디션/재고/유효 작업이 준비된 경우에만 해당 차량에 건다. 차량은 늦어도 정차점을 통과하기 전에 작업 수락 여부가 결정돼야 한다. 준비 불가면 해당 통과는 포기하고 이미 지난 차를 뒤쫓거나 뒤늦게 정지시키지 않는다. 복합 공정은 필요한 작업 슬롯을 안전하게 준비할 수 있을 때 수락하며 일부만 잡고 무기한 기다리지 않는다. 이미 부착된 미완성 부품은 기존 체결 규칙에 맞춰 중복 재고 소모 없이 처리한다.

한 공정 실행기가 작업 소유권과 게이트 해제를 책임진다. 기존 교통 관리의 감속·차간 거리·대기를 사용한다. 작업자만 정차형으로 변경하고 로봇팔의 이동 중 체결은 유지한다. 정산/퇴근/작업 취소/주체 전환/씬 종료/차량 풀 재사용 시 예약과 게이트를 해제한다. 집었으나 미부착이면 기존 환불 규칙, 부착한 미완성 부품은 차량에 남기는 규칙을 유지한다. LifeVersion으로 재사용된 차량에 오래된 명령이 적용되지 않게 한다.

차량이 정지했지만 손 도달/경로가 불가능하면 억지로 체결 완료시키지 않는다. 편집기에는 실패 지점을 표시하고, 메인은 작업 취소·정지 해제로 교통 교착을 막는다. 편집 검증으로 이런 설정의 저장/적용 가능 여부를 알려준다.

### 동선·리깅·주유

작업자 루트 이동, 부품 운반, 손 목표 궤적을 분리한다. 로봇과 사람의 곡선을 서로 공유하지 않는다. 차량 로컬 부착점을 따라 최종 손/부품 목표를 계산한다. 베지어라는 이유만으로 차체 관통을 허용하지 않으며 보행 경로를 샘플링해 차체/설비 충돌과 도달 불가를 표시한다.

기존 걷기 애니메이션 위에 손 IK, 제한된 어깨/상체 기울기, 발 지지 보정을 겹친다. 한 본을 기존 IK와 새 리그가 동시에 제어하지 않게 한다. 전신 솔버와 같은 효과를 보장하거나 임의 목표에 팔다리를 무한히 늘리지 않는다. 엔진·문·주유의 손 오차/도달범위/발 미끄러짐/관통을 검증하고 사용자 시각평가를 별도로 남긴다. 기존 A/B 앞문 테스트를 전부품 채택 근거로 사용하지 않는다.

주유는 노즐 거치/집기/운반/연결/주유/회수/반납, 작업자 대기·접근·정차 위치를 편집한다. 기존 수동 플레이어 거리/E 상호작용과 고용·자동 주유 기능을 보존한다. 고용 주유원은 후속 사용자 승인에 따라 같은 RobotKyle로 전환한다. 보급자·플레이어 외형은 기존 상태를 유지한다.

### 카메라·로봇 작업자

이동 키 유지 중에도 매번 수평 카메라 방향으로 이동 벡터를 계산한다. 몸은 실제 이동 방향으로 돌고 운반 앵커와 양손은 몸을 따른다. 우클릭 시 회전 응답을 빠르게 하며, 제자리에서는 카메라 수평 방향으로 몸을 맞춘다. S는 기존 요청처럼 반대 방향으로 몸을 돌려 이동한다. 커서 비잠금·UI 클릭 차단·맵 모드·차량 위 이동·점프를 보존한다.

고용 작업자의 게임플레이 루트/고용 배열/대기 위치를 유지하면서 RobotKyle 외형으로 연결한다. Animator, 손 앵커/IK, 발소리, 레이어와 충돌체를 재연결한다. 고용 전 비활성을 오류로 간주하지 않고 실제 고용 전후 활성 계층/렌더러 bounds/카메라/Avatar 정합을 확인한다. 원본 Worker FBX나 사용자가 수정 중인 아트 파일을 덮어쓰지 않는다.

## Testing Decisions

주 검증 경계는 **공정 설정 저장/로드 → 공유 실행기에 적용 → 차량/재고/주체의 관찰 가능한 결과**다. 내부 메서드를 그대로 따라가는 테스트 대신 메인과 프리뷰의 동작 일치를 확인한다. 기존 조립/캐릭터/서비스 검사와 풀·슬롯 검사 경계를 재사용한다.

- 저장→재로드→메인 적용에서 좌/우·±X 진행·공통 거리·개별 보정·차종 보정의 pose 일치. Undo/Redo와 미저장 전환도 확인한다.
- 앞문/엔진/바퀴 등 복합 공정과 주유를 포함해 작업자·로봇을 각각 검증한다. 지원하지 않는 조합은 명확히 표시한다.
- 픽업 시1차감, 슬롯 비움→손 이탈/1초 재충전, 재고0/보급, 연속 재시도/중단에서 수량·예약·풀 소유권이 정확해야 한다. 워밍업 후 핵심 집기/재충전 경로는 GC0/Instantiate·Destroy0을 유지한다.
- 작업 가능 정차→체결→출발, 재고0/휴식/퇴근 통과, 정차점 이후 늦은 수락 방지, 뒤차 대기, 취소/정산/풀 재사용에서 교착·고아 게이트가 없어야 한다.
- 0.1/1/20배 1회·반복·재시도에서 상태 순서/재고 일치와 종료 후 시간 복구를 확인한다.
- 메인 실제 고용 버튼 이후 로봇이 보이며 집기·체결·귀환한다. 카메라 W 유지 회전/제자리 우클릭/S 운반/맵/커서/차량 위 이동 회귀를 확인한다.
- 대표 공정에서 손/상체/발/부품 관통을 캡처하고 수치와 사용자 시각평가를 구분한다. 자동 검사 PASS를 자연스러움 승인으로 기록하지 않는다.

## Out of Scope

유료 전신 IK 도구 구매/도입, 새 캐릭터/차량 생성, 원본 FBX 스케일 수정, 새로운 경제 밸런스, 전체 아트 재배치, TestPartsScene 삭제, 플레이어 자동 보행, 실행 중 모든 게임 상태의 저장 시스템 재작성은 포함하지 않는다. 기존 세단 아트 검증 이슈는 별도로 유지한다. 새 차종은 등록·검증 구조와 프로필 선택을 지원하되 아직 매핑되지 않은 아트를 완료 차량으로 취급하지 않는다.

## Further Notes

구현 순서는 카메라/로봇 가시성 → 공정 설정 저장과 새 편집 씬의 최소 연결 → 정차 작업자·기존 로봇 공통 실행 → 경로/리깅·주유·복합 공정 → 배속/재시도/회귀 검증이다. 각 단계는 실제 저장/실행 결과로 확인한다. 미완성 기능을 UI 버튼만으로 완료 처리하지 않는다.

설계 승인 후 구현 계획과 의존성 티켓을 만든다. 새 커밋·푸시·Notion 게시 여부는 구현 완료 시 기존 승인 범위와 프로젝트 규칙을 확인한다. 이번 설계 작성은 그러한 작업의 완료 기록이 아니다.
