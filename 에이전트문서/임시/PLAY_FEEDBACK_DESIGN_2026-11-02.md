# 플레이 피드백 수정 설계 — 2026-11-02

상태: 사용자 2026-11-02 진행 승인. 구현·검증은 2026-11-03까지 이어짐.

## 목적과 제약
13개 플레이 피드백을 반영해 카메라를 돌려도 이동·운반 자세가 유지되고, 실제로 닿는 망치 작업과 이동하는 차량 위 플레이가 자연스럽게 이어지게 한다. 기존 Unity/Cinemachine/CharacterController 구조를 사용한다. 기존 수정와 11월 2일 교체된 Worker FBX를 보존한다. 새 유료 에셋/AI 생성은 범위 밖이다. 커밋·푸시는 별도 요청이 없으므로 하지 않는다. 플레이 중 C# 수정 금지. 부품 스택 배치 등 이전 저우선순위 항목은 이번 13개 완료를 막지 않는다.

## 접근 비교
- 개별 증상에 조건문 추가: 범위는 작으나 몸/루트/시선/운반 기준이 계속 달라져 뒤틀림과 원거리 조작이 재발할 수 있다.
- 기존 컴포넌트 안에서 시선·이동·행동 기준을 분리하고 접촉·거리 판정을 공용화: 현재 씬 참조를 유지하면서 피드백을 일관되게 해결할 수 있어 권장한다.
- 컨트롤러/애니메이션 패키지 전면 교체: 리그·IK·씬 재연결 범위가 크므로 보류한다.
사용자 확정: 우클릭 드래그는 항상 주변 보기이며, 카메라를 돌려도 현재 이동 방향을 유지한다. 권장 접근의 세부안은 아래와 같다.

## 1. 카메라·이동·행동 (요청 2, 9, 12)
카메라 궤도 yaw/pitch는 이동 기준축과 독립적이다. 우클릭 드래그로 주변을 봐도 플레이어 루트·몸·운반 부품을 함께 돌리지 않는다. 마우스 잠금은 다시 도입하지 않는다.
구현자 제안: 이동 키를 처음 누른 시점의 카메라 수평 방향을 이동 기준으로 잡고, 이동 키를 누르는 동안에는 카메라를 돌려도 그 기준을 유지한다. 키를 모두 놓고 새로 이동하면 새 카메라 방향을 기준으로 삼는다. WASD는 그 기준의 전후좌우이며, 몸은 실제 이동 방향을 바라본다. 첫 입력의 카메라가 수직에 가까우면 마지막 유효 수평 방향을 사용한다.
부품을 들 때 운반 앵커와 손 IK는 몸의 방향을 함께 따른다. S로 이동해 몸이 돌아도 부품이 과거 방향에 남지 않게 한다. 작업할 때는 행동 방향을 사용하고, 카메라를 뒤로 돌렸다고 팔이 몸을 관통해 목표를 쫓지 않도록 몸 앞의 도달 가능한 목표만 인정한다. 자유 시점에서 뒤쪽 물체를 원격 조작할 수 없다.
기존 임시 로봇 작업자에 연결되어 있던 걷기·달리기 클립과 전환을 확인해 현재 캐릭터에 재사용한다. 메시 교체는 기본 경로가 아니다. 점프는 기존 보유 클립에서 일반적인 도약/공중/착지 상태를 먼저 찾고, 충분하지 않으면 공식/원 제작자 자료를 조사한다. 새 다운로드·구매가 필수인 선택은 별도 확인한다. 물리 점프 높이와 공중 시간에 맞춰 애니메이션 전환을 정하며 발 뜸·착지 슬라이딩을 확인한다.
보급자는 같은 이동/운반 기준으로 확인한 뒤 상자 표시를 진단한다. 보급 상자라면 목적이 보이는 크기·손잡이 위치로 조정하고, 임시 디버그 박스라면 표시를 교체한다. 실제 부품으로 오인되는 표시를 유지하지 않는다.

## 2. 망치와 접촉 상호작용 (요청 1, 3, 4, 8)
망치 1회 동작은 1초다. 현재 공유 타이밍 구조이므로 우선 플레이어/NPC 공용 1초를 임시값으로 적용하고 NPC 작업 간격과 클립을 동기화한다. 새 클릭이 들어오면 진행 중인 스윙을 중단하고 0초부터 다시 시작한다. 빠른 연속 클릭은 되감아 재시도하는 모습이며 클릭 자체로 작업값이 오르지 않는다. 한 스윙의 실제 유효 접촉은 한 번이다. 재시작 순간의 이전 위치와 새 위치 사이를 타격 궤적으로 검사하지 않아 순간이동 타격을 방지한다. UI 클릭은 스윙을 재시작하지 않는다.
레버·차량 투입은 원거리 클릭/E 입력 경로를 제거하고 망치 머리의 실제 접촉으로만 실행한다. 레버는 한 스윙당 한 단계, 터널은 한 스윙당 차량 요청 한 번이다. 지도에서도 원거리 레버/투입 조작을 제공하지 않는다. 풀 대기 상태에서도 터널 타격 피드백은 실행한다.
HammerQuerySurface는 시뮬레이션 충돌이 아니라 실제 부품 메시 표면의 망치 접촉 검사용 캐시다. 현재 차량별/렌더러별 생성 때문에 루트가 늘어난다. 시뮬레이션용 차량 충돌과 합칠 수 있는지 검토하되, 서로 다른 용도 때문에 유지하는 경우 전용 RuntimeQueries 루트 아래 차량별 그룹으로 관리한다. 캐시가 같은 차·메시에 대해 중복 생성되지 않고, 차량 파괴/반환/풀 재사용 때 유효성이 유지되게 한다. 질의용 콜라이더가 플레이어를 막거나 공정 트리거를 건드리면 안 된다.

## 3. 터널·차량 물리 (요청 5, 6, 7)
터널 흔들림은 일정한 사인파 대신 불규칙한 짧은 충격·방향 반전·회전의 조합으로 만든다. 메시만 흔들고 상호작용/물리 충돌 기준은 안정적으로 유지한다. 대기열 가득 참 상태의 타격에도 흔들림과 가득 참 안내가 나온다. 흔들림 폭은 플레이로 조정하는 임시값이다.
차량 외관에 맞는 복합 충돌체를 우선 사용한다. 원본 프레임은 비다양체 문제로 MeshCollider를 피하라는 기존 규칙을 유지한다. 실제 보닛·지붕·트렁크와 측면에 근사하는 박스/캡슐/필요한 convex 형상을 사용하고 빈 공간을 큰 상자 하나로 막지 않는다. 외관/체결 상태 변화와 충돌체의 활성 상태를 맞춘다.
플레이어가 차량 위에 서면 발밑 지지 차량의 위치·회전 변화량을 적용한다. 벨트와 차량 속도를 중복 적용하지 않는다. 점프·차량 이탈·풀 반환·텔레포트 시 이전 지지체를 해제하고, 사라진 차량을 따라 순간이동하지 않는다. 공장 바닥·레일·이동 차량 사이를 건너며 점검한다.

## 4. UI·하루 종료·주유 (요청 10, 11, 13)
기존 임시 HUD/관리자 패널/고용·주유 팝업/정산 창에 일관된 화면 배율 기준과 여백을 적용한다. 작은 화면에서는 패널이 겹치지 않도록 재배치하거나 내용을 접고 스크롤한다. 클릭 판정도 같은 좌표 변환을 사용해 화면 표시와 일치시킨다. 최소 640×360, 1280×720, 1920×1080에서 확인한다. 정식 UI 아트 재디자인은 범위 밖이다.
하루 종료 정산은 표시 후 실제 시간 10초가 지나면 자동으로 닫고 다음 날로 진행한다. Time.timeScale=0에서도 카운트다운이 동작하며, 수동 다음 날 버튼을 유지한다. 수동/자동 진행이 같은 프레임에 발생해도 하루 증가와 정산 지급/초기화는 한 번만 실행한다.
주유 E 안내와 실행은 같은 근접·목표·도달 가능성 검사를 사용한다. 카메라와 차량 중심의 거리 대신 플레이어/손과 실제 노즐·주유구 위치를 사용한다. 빈손으로 노즐에 접근해 E로 집고, 손에 든 노즐을 주유구에 가까이 가져가 연결한 뒤 E 유지로 주유한다. 멀리서 E를 누른다고 노즐이 차량에 순간 연결되지 않는다. 이 2단계 노즐 취급은 구현자 제안이다. 원거리 이탈·부품 운반·팝업·정산에서는 진행을 취소/차단하며, 고용 작업자·자동 주유 경로를 회귀 검증한다.

## 검증과 완료 기준
- 카메라를 180도 돌려도 이동 키 유지 중 이동 벡터·몸·운반물의 관계가 유지된다. 키를 놓고 새로 이동하는 기준 전환도 확인한다.
- S 운반, 좌우 이동, 달리기, 도약/착지, 망치 작업 중 몸/팔 관통을 관찰한다.
- 1초 스윙, 접촉 전 재클릭, 접촉 후 재클릭, 빠른 연속 클릭, 허공·UI 클릭을 검사한다.
- 멀리 클릭/E로 레버·터널을 작동시킬 수 없고 실제 접촉은 한 번 실행한다. 대기열 full에서도 흔들린다.
- 차량 보닛/지붕/트렁크 탑승, 정지/저속/고속 및 회전 구간에서 따라가기, 점프 이탈, 풀 반환을 확인한다.
- 질의 캐시는 차량 수 대비 상한을 가지며 루트가 무한 증가하지 않는다. 공정 감지·로봇 체결을 회귀 확인한다.
- 작은 화면에서 주요 HUD와 팝업이 화면 안에 들어오고 클릭 위치가 맞는다.
- 정산 후 10초 자동 다음 날 및 수동 클릭과의 중복 방지를 확인한다.
- 주유 안내가 원거리에서 숨고, 노즐 운반/연결/해제와 고용 작업자 주유가 정상 동작한다.
- 검증 증거와 남은 플레이 판단은 HANDOFF/DEV_HISTORY_LOG에 구분해 기록한다. 컴파일 통과만으로 손맛·외관 완료를 선언하지 않는다.

## 구현자에게 맡기는 사항
컴포넌트 분할·메서드 이름, 콜라이더 세부 치수와 개수, 질의 캐시 재사용 구조, UI 기준 해상도와 폰트 최소 크기, 터널 충격 파형·세기, 점프 클립 선택과 보간 수치는 실제 씬/보유 리소스 조사와 검증으로 정한다. 사용자에게 추가 기능으로 단정하지 않는다.
