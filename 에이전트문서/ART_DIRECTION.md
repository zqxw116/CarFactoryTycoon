## 0. 한 줄 정의

> **"따뜻한 그림책 같은 공장"** — 무광, 낮은 대비, 따뜻하게 바랜 색, 얇은 갈색 선. 사실적인 공장의 구조와 실루엣 위에 손으로 칠한 듯한 몽글한 표면을 입힌다.

작업명: **Cozy Industrial (따뜻한 스타일라이즈드 인더스트리얼)**

## 1. 결정 경위

- 사용자는 두 방향 사이에서 흔들렸다. (1) 사실적인 탑다운 공장 이미지, (2) 따뜻하고 몽글한 아이소 도시 빌더 이미지.
- 판단 근거는 다음과 같다.
  1. **시점**: 게임은 근접 3인칭/1인칭 B급 공장 게임으로 전환됐다(`GAME_DESIGN.md`, 2026-10-27). 사실적인 스타일은 근접에서 텍스처 해상도, 메시 품질, IK 오차를 그대로 드러낸다. (1)번 이미지는 구 탑다운 방향의 그림이다.
  2. **AI 생성 에셋 통일성**: Tripo/Meshy 결과물은 에셋마다 텍스처 품질과 조명이 들어간 정도가 다르다. 사실적인 PBR로 가면 그 차이가 보인다. 무광에 낮은 대비, 공용 셰이더와 그레이딩을 쓰는 스타일라이즈드는 차이를 흡수한다. **일관성은 생성기가 아니라 셰이더, 조명, 팔레트가 책임진다.**
  3. **톤**: 넘어지고 날아가는 B급 물리 코미디는 몽글한 세계에서 귀엽게 읽힌다.
  4. **1인 개발 비용**: 사실적인 공장은 소품 밀도 요구가 감당할 수 없을 만큼 크다.
- 결론: **(2)번 이미지를 디자인 레퍼런스로 확정**한다. (1)번에서는 안전색(노랑, 주황) 체계와 기계 실루엣만 참고한다.

## 2. 레퍼런스 이미지 분석 (2번 이미지, aiboy.ai 도시 빌더)

> 레퍼런스는 타인의 작품이다. **표현 방식만 참고**하고, 이미지 자체를 image-to-3D나 학습 입력으로 쓰지 않는다. 건물이나 구도를 복제하지 않는다.

### 2-1. 디자인 정체성 (반드시 유지)

| 항목 | 관찰 | 우리 게임 적용 규칙 |
|---|---|---|
| **전체 인상** | 그림책이나 과슈 일러스트 같은 3D. 따뜻하고 조용하며 정돈되어 있다 | 공장이지만 "더럽고 위험한 곳"이 아니라 "정겹고 바쁜 작업장"으로 그린다 |
| **색감** | 전체가 살짝 누렇게 바랜(세피아/종이) 톤. 채도는 중간 이하. 순흑과 순백이 없다 | 전역 그레이딩으로 따뜻하게, 채도 -10~-15%. 가장 어두운 색은 짙은 갈색, 가장 밝은 색은 크림 |
| **명암 대비** | 낮다. 그림자가 옅고 부드러우며 그림자 색이 따뜻하다 | 그림자는 검정이 아니라 보랏빛 갈색 계열. 하드 섀도우는 약하게 |
| **재질** | 거의 전부 무광. 반사와 스페큘러가 사실상 없다. 표면이 매끈한 단색 면에 가깝다 | 기본 스페큘러 0. 금속도 "칠한 금속"처럼 무광으로 표현 (예외는 §2-3) |
| **선** | 창틀과 모서리에 얇고 진한 갈색 선. 굵지 않고 대비도 낮다 | 얇은 짙은 갈색 아웃라인. 검정 금지 |
| **형태** | 단순한 박스형 매스, 명확한 실루엣, 평평한 면. 각은 살아 있되 날카롭지 않다 | 큰 형태는 단순하게, 모서리는 작은 베벨 |
| **비율** | 건물은 현실 비율에 가깝다(치비 아님). 사람과 차는 작고 단순하다 | 기계와 차량은 현실 비율 기반에 살짝 뭉툭하게(§3-2) |
| **디테일 방식** | 텍스처가 아니라 **작은 반복 요소**(창문, 발코니, 실외기, 지붕 환기구, 벤치, 파라솔)로 밀도를 만든다 | 공장 디테일도 볼트, 리벳, 패널 이음선, 배관, 표지판 같은 **형태 반복**으로 만든다. 노이즈나 더러움 텍스처 금지 |
| **디테일 수준** | 중하. 멀리서는 풍부하고, 개별 오브젝트는 단순하다 | 오브젝트당 디테일은 낮게, 밀도는 배치 수로 확보 |
| **식생/유기물** | 동글동글한 덩어리 나무, 군집 배치 | 공장에서는 화분, 휴게실 식물로 소량 사용 가능 |
| **UI** | 크림색 종이 패널, 둥근 모서리, 얇은 갈색 테두리, 손그림 라인 아이콘, 주황 강조 | 정식 UI도 같은 언어로(§6) |

### 2-3. 레퍼런스에서 의도적으로 벗어나는 지점 (Claude 보완)

레퍼런스에 없는 특징을 추가하지 말라는 원칙은 **스타일 차원**에 적용한다. 공장 게임에 기능상 필요한 대상(컨베이어, 로봇, 스파크, 물)까지 금지하면 게임이 성립하지 않는다. 그래서 아래 예외를 **명시적으로** 둔다. 목록에 없는 이탈은 금지한다.

1. **차량 도장 하이라이트**: 레퍼런스는 전부 무광이다. 하지만 도장 공정(금속 → 매트 → 도색)이 이 게임의 볼거리이므로, 완성 도장에만 **넓고 부드러운 그려진 하이라이트 띠 1개**(툰 스페큘러)를 허용한다. 실제 반사(리플렉션 프로브, SSR)는 쓰지 않는다.
2. **빨강 예약**: 미체결 표시가 붉은색이다(`GAME_DESIGN.md`). 환경의 붉은 계열은 **채도 낮은 벽돌, 테라코타까지만** 쓴다. **고채도 빨강 `#E53935`급과 붉은 발광은 게임 정보 전용**이다.
3. **근접 시점 보정**: 레퍼런스는 원거리 하이앵글이다. 근접 3인칭에서 손에 드는 것(망치, 부품)과 체결 지점에는 **형태 디테일을 한 단계 더** 준다(볼트 머리, 패널 이음선). 텍스처 디테일은 추가하지 않는다.
4. **VFX**(스파크, 물, 미스트, 기포): 레퍼런스에 없다. 동일 원칙으로 확장한다. 단순한 형태(둥근 덩어리, 별 모양 스파크), 팔레트 내 색, 부드러운 블룸만 허용. 사실적인 연기와 불 시뮬레이션 금지.
5. **실내 조명**: 레퍼런스는 야외 주광이다. 공장은 실내이므로 **천창과 높은 창으로 들어오는 따뜻한 주광**을 주광원으로 삼아 레퍼런스 분위기를 유지한다.

## 3. 형태와 비율 규칙

### 3-1. 공통
- 큰 매스는 단순하게. 실루엣만 보고도 무엇인지 알 수 있어야 한다.
- 모든 외곽 모서리에 작은 베벨(현실 기준 1~3cm). 날카로운 칼각과 과한 둥글림(풍선 같은 형태)을 모두 피한다.
- 디테일은 형태로 만든다. 볼트, 리벳, 패널 라인, 손잡이, 배관, 케이블 트레이.
- 금지: 녹, 기름 얼룩, 긁힘 텍스처, 그런지, 데칼 남용, 사실적인 노이즈.

### 3-2. 대상별 비율
| 대상 | 규칙 |
|---|---|
| 건물 외피·구조물 | 현실 비율. 기둥, 철골 트러스, 천창이 반복 리듬을 만든다 |
| 기계·스테이션 | 현실 비율 기반, 두께를 10~20% 키워 뭉툭하게. 조작부(레버, 버튼)는 1.3배 과장 |
| 차량 | 현실 세단 비율 기반에 살짝 짧고 높게(휠베이스 -10%, 바퀴 +10%). 귀엽지만 장난감 같지는 않게. **부품 분리가 필수**(§5-3) |
| 부품·공구(손에 드는 것) | 1.2~1.5배 과장. 근접 시점 판독성이 우선 |
| 사람(플레이어, NPC) | **확정 필요** — 권장 4.5~5등신. 단순한 얼굴, 안전모와 작업복. Humanoid 리그 필수(IK 체결 재사용) |
| 소품 | 현실 비율. 군집 배치로 밀도 확보 |

## 4. 셰이딩·조명·포스트프로세싱

### 4-1. 셰이더: 솔루션 미정 (평가 중)
- **보유 셰이더를 전제로 하지 않는다**(사용자 지시 2026-10-28). 룩에 맞지 않으면 직접 제작하거나 구매한다.
- 평가 대상: `All In 1 3D-Shader`(캐시에 있으나 라이선스 미확인), `All In 1 Shader Nodes`, Flat Kit, Toony Colors Pro 2, Linework, Unity Toon Shader, GitHub 오픈소스, 직접 제작. 결과와 결정은 §4-1-1.
- 셰이딩 요구사항(솔루션과 무관하게 고정): 2~3단 부드러운 램프, **그림자색 직접 지정**(따뜻한 보랏빛 갈색), 무광, 도장 전용 툰 스페큘러 띠, SRP Batcher 호환, URP 17 Render Graph 지원.
- 아웃라인 방식: **화면 공간 엣지 검출(depth+normals)로 확정.** 인버티드 헐은 AI 메시의 법선 분할에서 끊기고, 픽셀 두께를 고정할 수 없으며, 창틀 같은 내부 모서리 선을 그리지 못한다.
  - 규칙: **1~1.5px 고정, 색 `#3B2F2A`, 불투명도 60~80%, 원거리에서 약화**.

#### 4-1-1. 평가 결과 (2026-10-28)

**확정(2026-10-28 사용자): Flat Kit 구매. 아웃라인은 유료 추가 없이, Flat Kit 내장 Outline과 Bill-SSOutline(MIT)을 룩데브에서 비교해 택1. Linework는 구매하지 않는다.**
- 셰이더 세부 튜닝은 에셋 생성 후로 미룬다.
- **개정 3(2026-10-28): Flat Kit은 할인 시 구매로 보류한다.** 그 전 앵커 판단은 임시 확인 환경(URP Lit Metallic 0·Smoothness 0 무광 + 따뜻한 조명 + 볼륨: 채도 소폭 감소, 화이트밸런스 따뜻하게)에서 하고, 선·단계 셰이딩은 구매 후 확인한다(`ASSET_GENERATION_PROMPTS.md` §4).

## 5. AI 에셋 제작 파이프라인 (Tripo / Meshy)

### 5-1. 원칙
1. **컨셉 이미지 → image-to-3D**를 기본으로 한다. text-to-3D 단독은 스타일 편차가 커서 보조용으로만 쓴다. 컨셉 이미지는 이미지 생성 AI로 만들되, 레퍼런스를 복제하지 말고 `ASSET_GENERATION_PROMPTS.md`의 컨셉 프리픽스로 만든다.
   - **컨셉 이미지에는 선과 강한 음영을 넣지 않는다.** 텍스처에 구워지거나 형상으로 오인된다. 그림책 느낌의 선은 셰이더(아웃라인)가 담당한다.
   - **스타일 앵커 2종**(2026-10-28 사용자 결정, 개정 3): `CHAR_Worker`와 단순 차량 `CAR_Body` 1대를 먼저 만들고 통과작을 이후 모든 컨셉 생성의 스타일 참조 이미지로 쓴다. 로봇팔은 기존 에셋이 있어 제외한다. 앵커 판단은 임시 확인 환경(무광 머티리얼 + 따뜻한 조명 + 볼륨)에서 한다. 생성기 간 스타일 표류를 막는 핵심 장치다.
   - AI 3D의 기본 경향(녹아내린 형태, 그려진 디테일, 얇은 구조 실패)은 프롬프트의 하드서피스 지시와 얇은 요소 배제로 대응한다.
2. 단일 오브젝트, 흰/중성 배경, 3/4 시점, 그림자 없는 고른 조명. **텍스처에 조명과 그림자가 구워지지 않도록** 요청한다.
3. 생성된 텍스처는 **알베도만** 쓴다. 메탈릭/러프니스 맵은 버린다(무광 원칙).
4. 통일은 엔진에서 한다. 공용 툰 셰이더, 전역 그레이딩, 아웃라인. 팔레트에서 크게 벗어난 에셋은 부위별 단색 팔레트 머티리얼로 교체하거나 재생성한다.
5. **검수 기준**(통과 못 하면 재생성): 실루엣이 명확한가 / 무광인가 / 구워진 그림자가 없는가 / 팔레트 범위인가 / 녹·때·노이즈가 없는가 / 기존 에셋 옆에 세웠을 때 같은 게임처럼 보이는가.

### 5-3. AI로 만들지 않는 것 (중요)
| 대상 | 이유 | 방법 |
|---|---|---|
| 컨베이어 벨트 | 스플라인 기반 경로라 고정 메시가 맞지 않는다 | Unity 스플라인 + 모듈 세그먼트(직선/곡선/끝단)를 수작업 또는 단순 모델링 |
| 공장 건물 외피(벽, 바닥, 기둥, 천창) | 모듈 스냅과 타일링이 필요하다. AI는 모듈 규격을 못 맞춘다 | ProBuilder/Blender로 모듈 키트 제작. 디테일 소품만 AI |
| 차체 + 체결 부품 | 23공정 체결 구조상 문, 후드, 트렁크, 바퀴, 시트, 유리, 램프가 **분리되고 피벗이 정확해야** 한다. AI는 한 덩어리로 뽑고, 따로 뽑은 패널은 차체 곡면과 맞지 않는다 | **외장 패널(Frame, Door×4, Hood, Trunk, Bumper)은 차체 1회 생성 → Blender 분리.** 차체는 닫힌 껍데기라 내부(시트·엔진)를 AI가 추출할 수 없으므로, 내부·독립 부품(바퀴, 시트, 엔진, 램프, 미러)은 확정 차량 컨셉 이미지를 스타일 참조로 넣어 부품 컨셉을 만든 뒤 image-to-3D로 생성하고 크기는 Blender/Unity에서 차체에 맞춘다(개정 3). 서비스의 파트 분할 기능은 시도해볼 수 있으나 품질 미검증이라 기본 경로가 아니다. 유리는 Blender 평면. 이름은 기존 `CarController` 부품 이름과 1:1. 도장 대상은 중성 연회색으로 받아 엔진에서 틴트 |
| 캐릭터 리그 | AI 자동 리그 품질이 불확실하다 | Tripo/Meshy 자동 리그 시도 → Unity Humanoid 매핑 검증. 실패 시 Mixamo |
